# CINEMA — бронирование билетов

Небольшой сайт кинотеатра на Node.js, Express и SQLite. Клиент и API запускаются одним сервером; открывать `index.html` как локальный файл не нужно.

## Запуск

Нужен Node.js 24 или новее (проверено на Node.js 24.22.1). Используется встроенная в Node.js SQLite: устанавливать Python, Visual Studio Build Tools или отдельный сервер базы данных не требуется.

```sh
npm ci
```

Если `.env` уже существует, сохраните его. При первой установке скопируйте `.env.example` в `.env` и задайте собственные `ADMIN_LOGIN`, `ADMIN_PASSWORD` и `SESSION_SECRET`. Для случайного секрета сессии можно использовать:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

```sh
npm start
```

Откройте `http://localhost:3000`. Другой порт задаётся через `PORT` в `.env`. По умолчанию расписание работает в часовом поясе `Asia/Qyzylorda`; изменить его можно через `CINEMA_TIMEZONE`. Дата и время сеанса вводятся по часовому поясу кинотеатра.

На Windows откройте папку с `server.js` в Проводнике, введите `cmd` в адресной строке и нажмите Enter. Выполняйте команды в появившемся терминале. После `npm start` оставьте окно открытым. Двойной щелчок по `index.html`, Live Server и GitHub Pages не запускают сервер Express.

Если в ранее скачанной версии `npm ci` выдаёт ошибку `node-gyp`, `better-sqlite3` или `Could not find any Python installation`, обновите исходные файлы проекта, включая `package.json`, `package-lock.json`, `database.js` и новый `sqlite.js`, затем снова выполните `npm ci`. Существующие `.env` и `cinema.db` сохраните. Предупреждение `ExperimentalWarning` о встроенной SQLite в некоторых версиях Node.js не мешает запуску; успешный запуск обозначается строкой `CINEMA: сервер запущен на порту 3000`.

## Посетитель

1. Посмотрите описание фильма, жанр, продолжительность и расписание.
2. Выберите фильм и будущий сеанс. Для каждого сеанса видны цена билета и число свободных мест.
3. Выберите места на схеме зала: 5 рядов по 8 мест, всего 40. Занятые места недоступны.
4. Введите имя, проверьте места и итоговую сумму, затем подтвердите бронирование.
5. После ответа сервера появится подтверждение с номером брони, фильмом, датой, временем, местами и суммой. Бронирование не списывает деньги: платёжный сервис не подключён.

Выбор места до подтверждения не удерживает его. Если другой посетитель успел забронировать место, сервер отклонит весь запрос и сайт обновит схему зала. Выберите оставшиеся свободные места и подтвердите заново.

## Администратор

Нажмите «Администратор» и войдите с данными из `.env`.

- Просматривайте бронирования и отменяйте их: места сразу освобождаются в базе.
- Добавляйте фильмы с описанием, жанром, продолжительностью и дополнительной информацией, удаляйте ненужные фильмы.
- Создавайте, изменяйте и удаляйте сеансы; просматривайте схему свободных и занятых мест.
- В одном зале нельзя создавать пересекающиеся сеансы. Учитывается продолжительность фильма.
- Сеансы с бронированиями защищены от изменения и удаления. Для удаления такого сеанса или фильма сначала отмените связанные брони.

Все изменения проверяются сервером; ошибки и результаты действий отображаются в интерфейсе. Доступ к операциям администратора требует авторизованной серверной сессии. Сессия хранится в SQLite и ограничена по времени; после истечения срока войдите заново.

## База данных и существующие данные

База `cinema.db` создаётся автоматически рядом с сервером и сохраняется между перезапусками. Не удаляйте её при обновлении: она содержит фильмы, сеансы и бронирования. Перед обновлением сделайте резервную копию при остановленном сервере. При использовании WAL учитывайте файлы `cinema.db-wal` и `cinema.db-shm`; надёжнее копировать базу после штатной остановки или использовать SQLite backup.

Существующая база из исходного проекта обновляется автоматически без удаления записей. Таблица распределения мест имеет уникальный ключ «сеанс + место», а запись брони и мест выполняется одной транзакцией. Защита действует на уровне SQLite, включая обращения из нескольких подключений. Если старые данные содержат противоречивые бронирования, миграция сообщает об ошибке вместо потери данных.

Для новой базы создаются демонстрационные фильмы и будущие сеансы. Для исходной базы с прошедшим расписанием и без броней будущие демонстрационные сеансы добавляются один раз. Удалённое администратором расписание при каждом запуске не восстанавливается. Позже расписанием управляет администратор.

В архив обновлённого проекта не включаются пользовательская `.env`, база данных и `node_modules`. При обновлении существующего сайта оставьте свою `.env` и `cinema.db` на месте, замените исходные файлы и выполните `npm ci`.

## Проверки

```sh
npm run check
npm test
```

API-тесты используют временные базы, а не рабочую `cinema.db`: они проверяют валидацию, права администратора, управление расписанием, расчёт стоимости, сохранение данных, отмену бронирования и конфликты мест.

`.env`, файлы базы и серверные исходники не раздаются посетителям. Для публичного размещения используйте HTTPS и задайте собственные надёжные учётные данные. Не добавляйте `.env` и рабочую базу в Git.
